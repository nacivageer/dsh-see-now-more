## 做什么

在上游的「按变化量筛选画面」内核上，补一层通话式交互：悬浮窗里能聊天、能中途插话、有历史和收藏。

与上游的差异（`dsh plugin add dsh-see-now` 装的是上游，不含这些）：

- 聊天窗、回合中途插话（barge-in）、历史与收藏
- 名字带 `-more`，**不发 npm**

## 分发与版本（2026-11-09 定）

**不发 npm。** 用源码安装：`git clone` → `node scripts/install-dev.mjs`（复制进本机 DSH 的 desktop profile，重启生效）→ 以后升级 `git pull` 后再跑一次；卸载 `--remove`。不发的原因：包里带着对 `window.py` 的大改，npm 那套 `prepack` 生成链会把它们冲掉（见「不做什么」）。

**版本锚点靠 tag + GitHub Release，不靠 npm 版本号。** 没有 tag 时：回滚只能翻 commit hash；别人 Watch 仓库勾 Releases、或订 `releases.atom`，全是空的 —— 订阅等于空转。

**版本号写在两处，变更说明写在第三处**，三处必须同值：

| 位置 | 字段 |
|---|---|
| `package.json` | `version` |
| `dsh.plugin.json` | `version` |
| `CHANGELOG.md` | `## [<version>]` 段 |

由 `test/version.test.mjs` 三条守住（含 `name` 一致）。任一不一致 `node --test` 直接红。

**发版五步**：

```
1. 改 package.json 与 dsh.plugin.json 的 version
2. CHANGELOG.md 补一段 ## [<version>]（同一提交）
3. node --test              # 版本/插件名/CHANGELOG 三条守卫会拦漏改
4. git commit && git tag -a v<version> -m "…" && git push origin main v<version>
5. 建 Release：tag 取 v<version>，正文取 CHANGELOG 那段；带 -more.N 后缀的标 prerelease
```

- 带 `-more.N` 的版本在 semver 里是**预发布版**（`0.2.0-more.1 < 0.2.0`），Release 里标 prerelease 才是诚实的信号。
- **`main` 可以领先 tag**：发版之后加的测试、文档、infra 提交不动 tag —— 发布锚点不跟着后续提交漂。
- 第 5 步没有 `gh` CLI 可用（本机未装），走 REST API：`POST /repos/nacivageer/dsh-see-now-more/releases`，token 从 `git credential fill` 取（**不打印**）。

## 不做什么

- **不发 npm**（2026-11-09）。上游 `dsh-see-now` 已占住这个名字；本包改名 `-more` 就是为了不撞车。
- **不跑 `npm run sync:window`**。它用上游覆盖 `examples/floating-chat/window.py`，而这里对它的改动很大；`prepack` 生成链已在公开发布准备里去掉了。
- **不承诺长期维护**：够用即停更，上游不自动跟进，本地改动也不保证能合回去。
- **不公开开发期的逐条记录**：CHANGELOG 只从 `0.0.4` 起记，`0.1.1 → 0.2.0` 的主体来自上游。

## 怎么跑 / 怎么查

```bash
node --test                                   # 单测（含版本/插件名/CHANGELOG 一致性守卫）
node scripts/install-dev.mjs --check          # 装进 profile 了没有、依赖缺什么
```

装完必须**重启 DSH**（插件树在进程启动时组合）。排查顺序：`--check` 的输出 → `~/.dsh/see-now-window.log`（悬浮窗自己的 stderr）→ 上游 README 的平台章节。
