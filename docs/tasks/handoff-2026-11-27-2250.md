## 一、做了什么

**1. 修「浮窗悄悄不再显示新消息」（`7974ec9`，本会话最重要的一个）**

- 从日志里 20:47 附近**连号五条** `chat poll error: 'utf-8' codec can't decode byte 0x8b in
  position 0` 追出来。不是「跳过一次轮询」，是**卡死到窗重启**：`ChatFeed.poll()` 拿字节位置
  （`stat().st_size` / `tell()`）去**文本模式** `seek`，而删除 / 重命名会话、自动清理都走
  `_write_chat_lines` → `os.replace` **整份换掉文件**；旧字节位置落到新文件里，可能正好是多字节
  字符的中段（`0x8b` 是 UTF-8 续字节）→ `UnicodeDecodeError`，而异常发生在 `_pos` 赋值之前 →
  之后每次轮询撞同一颗地雷。用户看到的是浮窗不再显示新消息，不报错、不提示。
- 两条修法：认文件索引 `(st_dev, st_ino)`（`os.replace` 必然换索引）→ 变了整份重读；增量读只在
  **最后一个换行**处推进，半行留给下一次。顺带修掉同源的另一半病：读到半行 → `parse()` 认不出 →
  读位置已越过它 → 那条消息永久丢失。`reload()` 也改成只认完整行、`_pos` 取实际消费字节数。
- 验收：`scripts/check-feed-poll.py` 17 条（切在多字节字符中间 / 整份重写 / 重写后继续收 / 清短重读），
  由 `test/feed-poll.test.mjs` 拉进 `node --test`。

## 二、坑（都踩过，别再踩）

- **合成点击的第一次会被「激活」吃掉**：窗不是前台时，第一次点击只做激活、Tk 收不到（坐标逐像素
  核过、窗也没被挡、`self_hits=5/5`，但列表没开；同坐标第二次才开）。脚本化那 5 项真发输入的
  验收时，要么点两次、要么先 `SetForegroundWindow`。
- **`_scratch/input_at.py` 必须先在进程里声明 per-monitor DPI 感知**：不声明时 `SetCursorPos` 收的
  是逻辑坐标，本机 150% 缩放下 (195,928) 会被当成 (130,619)，点歪。
- **窗内有调试入口，可以完全不碰鼠标验卡片落位**：`DSH_SEE_SETTINGS_OPEN=1` / `DSH_SEE_DELETE_OPEN=1`
  / `DSH_SEE_SET_DEBUG=1`（另有 `BIND_OPEN` / `EXPAND_AT` / `PRICE_CHIP` / `REFRESH` / `TRACE` / `WDA`）。
  重启时带上，卡片自己在 1.5 秒后弹出来，跑 `selftest-ui.py` + 截图就能验。本会话验「删除确认卡
  落在 `(150,317)`、尺寸 `500x278`，正合 `place_dialog` 算式」就是这么做的。
- **`selftest-ui.py` 现在不需要 `--hwnd` 了**（按属主认主窗）；只有想验「非主窗」时才用。
- **折叠态的窗在我的截图里是消失的**：收起那一下常开 `WDA_EXCLUDEFROMCAPTURE`（`window.py:2670`，
  `capturable: true` 也压不住），展开态才按 `capturable` 决定（本机展开看得见）。所以要拍折叠条 /
  气泡 / 折叠后的高度，**另开隔离实例带 `DSH_SEE_WDA=0`**（+ `DSH_SEE_REFRESH=99` 更稳），别对着
  真窗连抓几张空的就判断窗坏了 —— 先跑 `selftest-ui.py` 读窗口状态（它不抓屏）。机制与判据见
  `docs/决策记录.md`「收起态的窗抓不到」。
- **PowerShell 里给 `gh --jq` 传含 `\n` 的表达式会被吞**：改用 `gh release view --json body` 再
